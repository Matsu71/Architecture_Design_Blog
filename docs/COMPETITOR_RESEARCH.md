# 競合・参考サービス調査

調査日: 2026-09-11
方針更新: 2026-09-18

この調査では「建築を実際に見に行く人にとって日本一使いやすいサービス」を作るため、直接競合だけでなく、建築作品DB、建築メディア、建築祭の現地ガイドも比較対象にします。

## 0. 建築探訪マップ — 最重要直接競合

現時点で、本プロジェクトと最も用途が近い直接競合と位置付けます。建築を地図から探せること、建築家・年代・各種条件から探索できること、非常に広い収録範囲を持つことが強みです。

### 強み

- 日本各地の多数の建築を地図上で探索できる
- 建築家、年代、用途、受賞・選定等の軸から探せる
- 建築好きが旅行先や現在地周辺の建築を探す用途と相性がよい
- 長期間継続してデータが蓄積されており、網羅性が高い

### 本プロジェクトが正面から競争しない点

- 単純な掲載件数
- 建築作品を可能な限り多数収録すること自体
- マニア向けの網羅的な作品リストとしての規模

### 差別化する点

本プロジェクトは、収録件数を増やすことよりも、**旅行中に建築目的で訪れる価値があるか**を重視して選定します。一般的な施設まで広く表示するのではなく、「ここなら時間を使って見に行きたい」と思える建築を優先します。

各建築では単なる名称・設計者・竣工年だけでなく、次を重点的に扱います。

- なぜこの建築を見る価値があるのか
- 現地で見るべき場所・ディテール
- 建築家と作品の位置付け
- 構造、屋根、外壁、柱・梁、開口部、内装
- 木、石、煉瓦、コンクリート、金属、瓦、漆喰等の主要素材
- 光、動線、空間構成、設計意図
- 改修・保存の履歴
- 見学条件、営業時間、撮影可否、所要時間、周辺の立ち寄り先

競争戦略を一文で表すと、**「網羅性の建築探訪マップ」に対して、「観光価値の選定と1件あたりの解説品質」で差別化する**ことです。

## 1. archimap.info

URL: https://www.archimap.info/

### 強み

- 「建築ガイドマップ」として目的が明快
- 住所・場所から検索できる
- インストール・ユーザー登録不要
- スマートフォンから利用可能
- 所在地、用途、受賞など複数のインデックスを持つ
- 2026-09-11時点で東京都ページは320件を掲載

### 本プロジェクトが上回るべき点

- 初心者にも伝わる「何がすごいか」の説明
- 写真中心の発見体験
- 見学可否・公開情報・現地で見るポイント
- 周遊コース
- データの検証日・出典管理
- モバイルUIの情報階層
- 歴史・構造・設計意図を段階的に読める詳細ページ

参考:
- https://www.archimap.info/
- https://www.archimap.info/architecture-index.cgi?sort=location&tag=%E6%9D%B1%E4%BA%AC%E9%83%BD

## 2. TECTURE / TECTURE MAG

URL: https://www.tecture.jp/

### 強み

- 建築・空間デザインの大規模データベース
- 建築種類、用途、工事種別、構造、面積など専門的な条件で検索できる
- 建材・家具・メーカー情報までつながる
- 設計者／チーム単位でも作品を追える
- TECTURE MAGには地域・用途別の豊富な建築記事がある
- 2026-09-11時点のTECTURE MAG「PROJECT」では日本1,693件、東京472件、神奈川122件など多数のプロジェクトが確認できる

### 本プロジェクトとの違い

TECTUREは設計者・建築業界側の情報探索に非常に強い。本プロジェクトはそこへ正面から競争するのではなく、**一般ユーザーが実際に建築を訪ねる体験**に特化する。

上回るべき領域:
- 地図起点の観光導線
- 「今、見に行けるか」
- 建築初心者向けの要約
- 近隣建築との組み合わせ
- 半日／1日の周遊
- 近代・歴史建築を含む横断性

参考:
- https://www.tecture.jp/
- https://mag.tecture.jp/project/

## 3. architecturephoto.net

URL: https://architecturephoto.net/

### 強み

- 建築作品を継続的に紹介する編集メディア
- 写真と設計者によるテキストを重視
- 建築の背景や設計意図まで読める
- タグが豊富
- 写真権利を明確に扱い、許諾を得た写真を掲載する方針を公開している
- 建築デザイン分野で大きな読者基盤を持つ

### 本プロジェクトが学ぶ点

- 写真を単なる装飾ではなく建築理解の中心に置く
- 設計者・撮影者・出典の権利を明確に扱う
- 表面的な紹介ではなく「なぜこの建築になったか」を説明する

### 本プロジェクトとの差別化

- ニュースではなく、長期利用できるスポットDB
- 地図・訪問・周遊に重点
- 一般ユーザー向け要約を標準装備

参考:
- https://architecturephoto.net/
- https://architecturephoto.net/about/

## 4. 東京建築祭

URL: https://2026.kenchikusai.tokyo/2026/

### 強み

- 建築を「実際に訪問する」体験設計が非常に強い
- 公式プログラムマップを提供
- スマートフォンで建築の位置関係を確認できる
- 特別公開、展示、ガイドツアーなど訪問目的が明確
- 特別公開建築に音声ガイドを用意
- 地図と公開情報をガイドブック的に使えるアプリも提供

### 本プロジェクトが学ぶ点

- 現地利用では「作品情報」だけでなく、公開条件と位置関係が重要
- 建築を見る前に短い音声／要点解説があると体験価値が上がる
- 当日の変更情報を扱える仕組みが必要

### 差別化

東京建築祭は会期中の体験が主目的。本プロジェクトは年間を通じて使える恒常的な全国建築ガイドを目指す。

参考:

- https://2026.kenchikusai.tokyo/2026/04/05/004810/
- https://2026.kenchikusai.tokyo/entry/

## 5. 京都モダン建築祭

URL: https://kyoto.kenchikusai.jp/

### 強み

- エリア、開催日、企画種別など、現地周遊に必要な検索軸が明快
- 普段入れない建築の特別公開という強い体験価値
- 建物ごとの撮影可否、バリアフリーなど訪問者向け情報を扱う
- 2026年は約150件規模の参加建築が案内されている

### 本プロジェクトが学ぶ点

- 「撮影可否」「バリアフリー」「公開条件」は建築観光で重要なデータ
- 建築を単体で紹介するだけでなく、地域単位で回遊させる
- 交通との連携は周遊価値を上げる

参考:
- https://kyoto.kenchikusai.jp/

# 勝ち筋

## 0. 件数競争ではなく「選定の信頼」を作る

登録数を主要な成功指標にしません。「この地図に表示される建築なら、旅行中に行く候補として検討する価値がある」と利用者が感じられることを優先します。重要度の低い建築が大量に混ざって目的地を選べなくなる状態を避けます。

## 1. 「近くのすごい建築」を最短で見つける

トップページで検索より先に地図を見せる。現在地、駅、エリア、観光地を起点にする。

## 2. 1件あたりの説明品質を上げる

単なるスペック集ではなく、以下を必須にする。

- 30秒で分かる魅力
- 現地で見るべき3点
- 建築史上の意味
- 設計の工夫
- 見学情報
- 一次資料

## 3. データ量とUI密度を分離する

内部データは多く持ってよい。しかし初期画面は簡潔にし、詳細は段階的に開く。

## 4. 「作品」と「訪問可能なスポット」を区別する

優れた住宅でも私有地なら、観光目的で無責任に誘導しない。外観見学の可否、公開範囲、撮影可否を明確に持つ。

## 5. ルート機能を競争力にする

建築単体の記事数だけでは大規模DBに追いつくのに時間がかかる。そこで、地理・テーマ・時間を組み合わせた周遊体験で早期に差別化する。

# 直近で追うKPI

- 関東で「行く価値がある」建築の登録数
- 一次情報確認済み比率
- 主要建物の写真保有率
- 見学情報の確認日が一定期間内にある比率
- 地図から詳細までの操作回数
- 1エリアあたり作成可能な周遊コース数
- ユーザーが地図→詳細→公式サイトへ到達する率


# 長期的な発展可能性 — 建築から観光マップへ

建築向けに作る地図、重要度、詳細解説、訪問条件、周遊ルートの仕組みは、将来的に高品質な観光マップへ拡張できます。

候補カテゴリ:
- 自然の名所・景勝地
- 庭園・公園
- 美術館・博物館
- 文化施設
- 歴史・文化遺産
- 地域を代表する観光施設

ただし、拡張後も「何でも載せる地図」にはしません。建築と同じく、**旅行者が実際に時間を使って訪れる価値がある場所を選び、質の高い解説を付ける**ことを共通原則にします。初期は建築でこの編集基準とユーザー体験を確立してから拡張します。
