# 参考サイトと構成の選定

調査日：2026-09-14。既存UIを維持する前提ではなく、建築を探す・読む用途から再検討した。

## 調査と採否

| 対象 | 確認した構成・根拠 | 今回の採用 | 採用しないもの・確認範囲 |
| --- | --- | --- | --- |
| 建築探訪マップ | Appleの編集記事が、地図のピン、建築家検索、設計・カテゴリ・竣工年・住所を紹介 | 場所から探す導線、建物と基本情報の組合せ | 紹介記事の確認。アプリの全画面・実機操作の網羅評価ではない |
| 日本建築めぐり／建築パース.com | 都道府県と建築家の二つの索引。短い具体的な分類名 | 地域・建築家の検索、地域別の静的一覧 | ページの複雑な旧式構造や文字列のコピーはしない |
| Divisare | Cities、Elements、Materiality、Types等の分類。サイト自身が新着偏重でなくテーマごとの整理を説明 | 場所・設計者・用途から探し、部位・材料へ深掘りする構成 | 巨大メニューをトップに全部展開しない。写真・図・固有の装丁は転用しない |
| architecturephoto | 作品・設計者を明示する建築情報メディア | 設計者と作品の関係、出典を明示する姿勢 | ニュース向けの長い説明型見出しを、建物記事の題名には持ち込まない |
| TOTOギャラリー・間 | 展覧会情報、概要、交通等の目的別案内 | 解説と訪問情報を分ける簡潔な導線 | 展覧会中心のトップをそのまま建物索引に流用しない |
| ArchDaily Projects | 作品検索ページを調査候補にしたが、取得できた本文が限定的 | 今回の主要な判断根拠にはしない | フィルターの全仕様・操作性を確認済みとはしない |
| japan-architects | 調査候補。ページ取得が不十分 | 今回の主要な判断根拠にはしない | 未取得のレイアウトを推測で評価しない |
| archi-map | 建築マップ系の比較候補として確認 | 網羅性を比較する候補として保持 | 旧来のフレーム構造は採用しない |

Appleによる「おすすめのアプリ」への選定は確認できた。ただし全参考サイトについて共通条件の閲覧数・可読性テストを測定したわけではなく、「人気No.1」「読みやすさが客観的に実証された」などの順位は付けない。

## 選定した主軸

**建築探訪マップの場所検索 + 日本建築めぐりの地域・建築家索引 + Divisareの分類整理**を主軸にする。記事の訪問案内は施設系サイトの目的別情報分離を参考にする。

トップは検索、地域・建築家・用途、地図と建物一覧の順。長いサービス紹介、特徴を並べる宣伝パネル、開発文書への主要導線を外す。PCは地図と一覧を並べ、狭い画面は切り替える。建物を選ぶと記事または実際の座標へ移動する。

記事は、建物名、一行の特徴、基本情報、見どころ、構造・素材、見学、出典の順。素材の詳細と未確認事項は折りたたむ。設計者名をタイトルの直下と基本情報で二重に繰り返さない。

## 文字・色・余白

- 題名は公式の建物名を基本にする。棟を区別する必要があるときだけ「本館」「第一体育館」等を加える。
- 「見どころ」「構造・素材」「見学」「出典」のような短い具体語を使う。長い抽象的な宣伝文や「未来を切り開く」型のコピーは置かない。
- 一覧の説明は一文または短い体言止めとし、原則60文字以内。本文には別の厳しい短文化制限を設けず、確認できた情報を必要な深さまで説明する。
- 色は内容を邪魔しない白・オフホワイト・濃い文字を基調とし、操作色を落ち着いた緑に統一した。特定サイトの配色値を抽出して複製したものではなく、複数の情報型構成を矛盾なく統合するための独自の調整。
- 通常本文と補助情報の文字階層を分ける。記事の横幅は最大820px。モバイルは余白を残し、細い画面で横スクロールさせない。

公開情報から分類・見出し・導線を確認した調査であり、全候補の画面を同条件で撮影・計測した視覚比較や読者テストは未実施。改善後の読者テストは別途必要。
