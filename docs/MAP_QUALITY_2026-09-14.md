## 操作の改善

検索と地域を常時表示し、建築家・用途・年代・見学・並び順は「絞り込み」にまとめた。URLに詳細条件があればその欄を自動で開き、設定済みの条件数を表示する。前回選定した情報構造の整理を継続し、別の宣伝的な見出しは追加していない。

日本語変換中の文字列では絞り込みを走らせず、変換確定後に反映する。ホバーでは選択が変わったピンとカードだけ更新し、全ピンのDOMを毎回作り直さない。地図ライブラリが読めない場合は一覧を維持し、空の地図だけに切り替わらないようにした。写真の表示・出典と、ピンの位置精度ラベルも追加した。

## 再現方法と変更の保護

通常のデータ更新は `data/buildings.json` を変更し、`npm run build:articles`、`npm run validate`、`npm test` で再生成・検査する。写真と建物輪郭を同時に更新するときは、引用元、棟の同定、利用条件も更新する。

今回の移行は `data/revisions/map-quality-20260914.json` と `scripts/apply-reviewed-revision.mjs` に保存した。元データのハッシュが一致しない場合は書き換えず停止する。一致済みの移行は再適用しない。通常のサイトビルドで過去の移行を繰り返さない。

`publication.yml` は作業ブランチの明示したリクエストでのみ動き、読み取り権限で再生成・検査したあと、別の限定した書込みジョブで生成物を同じ作業ブランチにコミットする。mainを自動更新せず、同時更新時には非強制pushを失敗させて保護する。書込み用権限で外部取得・ブラウザ検査を実行しない。

## 実行結果

公開前の組み立てワークフロー34806536515で、ハッシュ保護付きの移行、写真生成、13本の記事再生成、データ検査、Node 47項目と実ブラウザ142項目が合格した。元の13件版から移行した20個の生成ファイルは、ローカルで確認したファイルと全てバイト一致した。写真も原画像・縮小版のハッシュが一致した。

Chromium・WebKitで1440、768、390、320pxを確認。個別ピン、30件の重なり選択、HTTP上の記事遷移、詳細条件のURL復元、IMEイベント中の待機、写真デコードとクレジット、横はみ出しを検査した。ホバーで全マーカーを作り直さないことも確認した。背景タイルは別の通信試験で両ブラウザ各20枚を取得した。実際の地図画面と写真付きの記事画面はスクリーンショットでも確認した。

通常のブラウザ操作試験は改変しないLeaflet配布物をハッシュ確認して読み込み、タイル通信だけを遮断している。30件の重なりには明示した合成レコードを使う。公開ホストの確認はmain反映後の `Architecture quality` の `public-report.json` を参照し、この組み立て試験とは区別する。公開サイト検査ではライブラリ・通信・ページ遷移を差し替えず、対象版のファイルハッシュを先に照合する。

IMEはブラウザイベントの検査であり、日本語入力システムの実機試験ではない。WebKitもiPhone実機ではない。地理的・史実的な正しさは自動試験だけでは保証しない。旧オフラインDOM検査45項目も再実行したが、実ブラウザ142項目に含めて水増しはしない。

## 残る優先事項

公開入口の照合、庭園美術館本館の個別輪郭、残り10件の棟位置の確認を進める。駅舎、図書館、学校、住宅、宗教建築など、美術館以外の関東建築の収集も必要。写真は未掲載の建物が多く、全国網羅・読者による使いやすさ評価・iPhone実機試験は未完了。13件という区切りを最終目標の達成にはしない。
